工业信息安全技能大赛复赛 - 海南车联网/信创密码题

一周前去了海南参加了工业信息安全技能大赛的复赛，本来以为都是一些工控的赛题，没想到里面“塞”的东西还挺五花八门的。不过自己只做了一点在“车联网”模块里的密码题，“信创”里的密码题是一道也没做出来，太惨了。

XA_CTF_ByPass

刚开始拿到一个 npz 文件，以为是啥杂项题（实在是太不熟悉了），同事说今年国赛出现过这玩意儿，是测信道攻击，随后甩来一个 wp： https://mp.weixin.qq.com/s/7bWCDKL0NKIDESAIJFaugg。看了一下，几乎和这道题是大差不差的，，那不是手拿把掐的进行一个秒杀？拿着这份官网wp最下面的那个脚本直接就能出 flag 了。

拿分归拿分，赛后再简单看看这到底是个什么高级玩意儿。

首先如果直接用 7z 打开这个 npz 文件，可以看到里面有四个文件

也可以用 numpy 去读

import numpy as np
dataset = np.load(‘./ctf_ciscn_2024.npz’, allow_pickle=True)
print(dataset.files)

[‘index’, ‘input’, ‘output’, ‘trace’]

不过不是每一个文件都是有数据的

所以这里有用的都是 index，input，trace 这三个文件，

打印一下内容

那么进行合理的猜测，总共是 440 份数据，分成 11 组。每一组 40 个数据，也就是 input 遍历的 40 个字节 abcdefghijklmnopqrstuvwxyz0123456789_!@# ，其中每一个字节都对应了一份 trace 数据。

那么将第一组的 trace 数据画个好看的图对比一下

import matplotlib.pyplot as plt

trace = dataset[‘trace’] # 获取trace
num = len(dataset[‘trace’]) # 数量
for x in range(44):
    plt.figure(figsize=(20, 2))
    plt.grid(True)
    plt.plot(trace[x][:
1000]) # 绘制
    plt.show()

可以看到对于第 0 组数据， _ 这个字符的图片和其他的有点不一样（当然在写这篇文章的时候，我是在知道答案的情况下，带着目的找过去的）

意思就是，对于 flag 的第一个字符，遍历了 44 个种可能，其中有 1 个是对的，有 43 个是错的。错误字符是一种轨迹，正确字符是一种轨迹。对于每一组，我们只需要找到那个特立独行的轨迹就行了。

从44个数里找出那个不一样的数，一个简单的思路就是，计算这 44 个数的平均值，然后找出那个和平均值相差最远的数就行了。

这里引入可以 “一键计算” 平均值的函数 np.mean(data, axis=0)

那么怎么区分出那条“特立独行”的轨迹呢？一个想法是，可以计算每个点的差值平方和，找出最大的那个。

for i in range(44):
    diff = 0
    for j in trange(len(dataset[‘trace’][i])):
        diff += (dataset[‘trace’][i][j]-avg_trace[j])**2
    print(diff)

但是运行起来超级慢

于是这里引入一个 numpy 的相关系数函数 numpy.corrcoef

from numpy import corrcoef
for i in range(44):  
    print(corrcoef(dataset[‘trace’][i],avg_trace))

很明显，第一行第一列的这个值越大，两条曲线就越“像”

from numpy import corrcoef
for i in range(40):  
    print(dataset[‘input’][i],corrcoef(dataset[‘trace’][i],avg_trace)[0][1])

于是我们就找到了第一组的正确字符，后面几组也是一样了

for i in range(0,440,40):
    avg_trace = np.mean(dataset[‘trace’][i:i+40],axis=0)
    for j in range(i,i+40):
        if corrcoef(dataset[‘trace’][j],avg_trace)[0][1] < 0.5:
            print(dataset[‘input’][j])

这道题是找和其他轨迹相关性最差的那条，另外一题则是反过来。

XA_CTF_AES128

（PS：这道题是给了flag的密文，让我们通过分析找到密钥然后去解密，不过比赛的时候忘记留密文了。）

起手式还是一样，看一下数据的构成

一共是五十组输入输出数据和对应的轨迹。那么如何利用这五十组功耗分析出密钥呢？具体参考 @Xnney 的 https://github.com/X3NNY/chipwhisperer-cn/blob/main/archive/CPA/%E6%89%8B%E5%8A%A8CPA%E6%94%BB%E5%87%BB.ipynb

总而言之，是根据 AES 第一轮输出的汉明重量与轨迹的相关性来确定密钥的。（因为 AES 第一轮用的轮密钥就是初始密钥）

当我们画出一万个采样点的图的时候

会发现这个图还是挺有规律的，要么是五个“针脚”，要么是三个“针脚”，猜测程序在进行解密运算（也就是幂运算）的时候应该用的是倍增法，会根据私钥 d 的不同比特 ( 1 或者 0) 执行不同的运算，如果是 0 则只有乘法运算，是三个“针脚”；如果是 1  则多一步加法运算，是五个“针脚”。

比赛的时候以此为规律，分段作图，人肉记录，最终是把这个私钥给 “硬” 提取了出来。不过要是遇到 RSA-2048 或者 RSA-4096 那可就盖了帽了。

根据图像，我们可以大致判断这个针脚是小于 -0.15 的，

B = -0.15
dataset = dataset[‘trace’][0]

INDEX=[]
for i in range(len(dataset)):
    if dataset[i] < B:
        INDEX.append(i)
print(INDEX)

这 “五个针脚” 的地方一搓共有二十多个小于 -0.15 的数据，而“三个针脚”的地方一搓大概只有十多个，

这里我们从第 1500 个数据往后统计，（因为从这里才开始有规律起来的）简单处理一下，判断一搓数据具体有多少个，如果下一个数据离当前数据太远了（超过 200），那就判定其属于新的一搓。

B = -0.15
dataset1 = dataset[‘trace’][0][1500:]

INDEX=[]
for i in range(len(dataset1)):
    if dataset1[i] < B:
        INDEX.append(i)
print(INDEX)

TIMES=[]
time=0
window = 200
for i in range(len(INDEX)-1):
    time += 1
    if INDEX[i+1]-INDEX[i] > window:
        TIMES.append(time)
        time=0
print(TIMES)

可以看到还是很规律的，一搓大于 20 个则记为 ‘1’，一搓小于 20 个则记为 ‘0’ 即可。不过最后测试发现不对，那可能是在开头不太规律的那一搓还有一个 ‘1’，加上就可以了。
