Python 正则表达式实战教程：从 re.search 到工程化用法

很多人对正则表达式的第一印象是“一串看不懂的符号”。其实大部分模式都可以拆成四个问题：

  1. 匹配什么字符？ 字面量、字符类、通配符。
  2. 匹配多少次？ *、+、?、{m,n}。
  3. 从哪里开始、到哪里结束？ 锚点、边界、前后查找。
  4. 如何分组和选择？ 捕获组、命名组、分支。

本文从 Python 的 re 模块讲起，覆盖常用 API、核心语法、分组与断言、替换与切分、性能和实战配方。示例基于 Python 3.11+，主要片段已在 Python 3.14 上验证。

1. 正则适合解决什么问题

正则擅长处理结构相对固定、长度有限、上下文简单的文本：

  • 表单格式校验：手机号、日期、邮编、简单邮箱。
  • 日志解析：从一行日志里提取 IP、时间、状态码。
  • 文本清洗：合并多余空格、去掉不可见字符。
  • 批量替换：把 YYYY-MM-DD 改成 DD/MM/YYYY。
  • 快速提取：从一段文本中找到 URL、金额、订单号。

它不擅长处理嵌套结构和完整语法：

  • 不要用正则解析 HTML、XML、JSON、CSV。
  • 不要试图用一条正则完整实现 RFC 5322 邮箱标准。
  • 不要用正则解析带嵌套括号的表达式。

这些场景应该使用专门的解析器。正则很强，但不是万能解析器。

3. re 模块的常用 API

函数 作用 返回值
re.match(pattern, s) 从字符串开头尝试匹配 Match 或 None
re.fullmatch(pattern, s) 整个字符串必须完全匹配 Match 或 None
re.search(pattern, s) 扫描整个字符串，返回第一个匹配 Match 或 None
re.findall(pattern, s) 返回所有匹配 list[str] 或 list[tuple]
re.finditer(pattern, s) 返回所有匹配的迭代器 Iterator[Match]
re.sub(pattern, repl, s) 替换匹配内容 str
re.subn(pattern, repl, s) 替换并返回替换次数 (str, int)
re.split(pattern, s) 按模式切分 list[str]
re.compile(pattern) 预编译模式 Pattern 对象

3.1 match、search、fullmatch 的区别

这是初学者最容易混淆的一组 API：

  • match：只在开头尝试，但不要求匹配到结尾。
  • search：在任意位置找第一个。
  • fullmatch：要求整个字符串从头到尾都匹配。

**做格式校验时优先用 fullmatch**，不要用 match，也不要在模式里随手加 ^...$ 来代替。

3.2 findall 的返回值会受分组影响

规则很简单：

  • 没有捕获组：返回完整匹配字符串的列表。
  • 有一个捕获组：返回该组内容的列表。
  • 有多个捕获组：返回元组列表。
  • (?:...) 是非捕获组，不会出现在结果里。

如果结果类型和预期不一致，先检查模式里有没有捕获组。

3.3 预编译模式

re.compile() 返回 Pattern 对象，之后可以反复调用 .search()、.findall()、.sub() 等方法。

re 模块内部会缓存最近使用过的模式，所以编译本身不是“用了就快十倍”的魔法。预编译的主要价值是：

  • 把模式集中定义，避免散落在代码里。
  • 给模式起名字，提升可读性。
  • 在循环或热点路径中避免重复查找缓存。

4. 语法核心：字符、量词与锚点

4.1 字符匹配

写法 含义 示例
a 字面量字符 cat 匹配 cat
. 除换行外的任意字符 a.c 匹配 abc、a c
[abc] 字符集合中的任意一个 [aeiou] 匹配元音
[a-z] 范围内的任意一个 [0-9] 匹配数字
[^0-9] 不在集合中的任意一个 匹配非数字
\d 数字 默认支持 Unicode 数字
\D 非数字 \D+
\w 单词字符 字母、数字、下划线，默认支持 Unicode
\W 非单词字符
\s 空白字符 空格、\t、\n 等
\S 非空白字符

几个容易忽略的细节：

  • 在字符类 [...] 里，.、*、+、? 通常只是普通字符，不需要转义。
  • ] 如果出现在字符类开头，可以表示字面量；放在其他位置通常需要转义。
  • - 放在开头或结尾表示字面量，例如 [-a-z]；放在中间表示范围。
  • [.] 只匹配真正的句点，而 . 匹配任意字符。

4.2 量词：匹配多少次

量词 含义
* 0 次或多次
+ 1 次或多次
? 0 次或 1 次
{m} 恰好 m 次
{m,} 至少 m 次
{m,n} m 到 n 次

贪婪与懒惰

默认情况下，量词是贪婪的：尽可能多匹配。在量词后面加 ? 会变成懒惰，尽可能少匹配。

贪婪和懒惰没有绝对的好坏，取决于你要匹配的边界。处理带引号的字段时，通常用“排除分隔符”的写法更稳：

[^"]* 不会越过下一个双引号，比 .*? 更直观，也更不容易在复杂文本中失控。

在量词后加 + 可以构成占有量词，例如 *+、++、?+、{m,n}+。它和贪婪量词的区别是：匹配后不回溯。

\A 只匹配字符串开头
\Z 只匹配字符串结尾

10.2 灾难性回溯

某些嵌套量词会让正则引擎尝试大量组合：

(a+)+ 在失败时会反复尝试不同的分组方式。输入越长，回溯路径越多，这就是常说的 ReDoS（正则拒绝服务） 风险。

可以这样规避：

  • 用更精确的字符类和边界，减少无意义的回溯。
  • 避免嵌套量词，例如把 (a+)+ 改成 a+。
  • 对固定格式做校验时，直接用 fullmatch()。
  • 在 Python 3.11+ 中，确认语义允许时使用占有量词或原子组。
  • 对不可信输入限制长度，或放到独立进程中处理。

Python 标准库 re 没有内置超时参数。如果必须对不可信输入设置超时，可以考虑第三方 regex 模块的 timeout 参数，或在进程/线程层面做隔离。

14. 常见坑清单

坑 1：把 match 当成 fullmatch

格式校验用 fullmatch()。

坑 2：以为 $ 就是绝对结尾

严格结尾用 \Z，或者直接用 fullmatch()。

坑 3：忘记 . 不匹配换行

跨行文本要加 re.S，或者用 [\s\S]、[^x] 这类写法。

坑 4：findall 结果类型突变

模式里加了捕获组，findall() 可能从字符串列表变成元组列表。用 (?:...) 去掉不需要的捕获。

坑 5：贪婪匹配吃掉太多内容

坑 6：在中文里滥用 \b

中文属于 \w，\b 不会在任意两个汉字之间成立。中文分词不要依赖 \b。

坑 7：替换模板里的反斜杠

\1、\g<name> 在替换字符串中有特殊含义。需要字面反斜杠时，用转义或函数替换。

坑 8：空匹配导致意外结果

\d* 可以匹配空字符串，所以会在没有数字的位置也插入替换内容。需要“至少一个数字”时用 \d+。

坑 9：给 Pattern 方法传 flags

flag 要在 compile() 时指定。

坑 10：忘记原始字符串

写正则时默认加 r，除非你有明确理由不这么做。

15. 最佳实践

  1. 校验用 fullmatch，提取用 finditer。
    findall 方便，但结果会受捕获组影响；需要位置和分组信息时用 finditer。

  2. 模式加 r，长模式用 re.X 写注释。
    可读性差的正则，维护成本比多写几行代码更高。

  3. 给分组起名字。
    (?P<year>...) 比 group(3) 更难写错。

  4. 在模块级预编译。
    尤其是循环中反复使用的模式。

  5. 不要把用户输入直接拼进模式。
    用 re.escape()，或者改用字符串方法。

  6. 不要用正则解析嵌套格式。
    HTML、JSON、XML、CSV、表达式语法，都有更合适的工具。

  7. 为不可信输入设置边界。
    限制长度、隔离进程、使用带超时的第三方库，避免 ReDoS。

  8. 准备正反样例。
    一条“能匹配”的样例不够，还要有“不能匹配”的边界样例。

  9. 能不用正则就不用。
    startswith()、in、split()、partition() 往往更清晰、更快。

  10. 把正则当成代码来维护。
    命名、注释、测试、代码审查，一个都不能少。

17. 总结

正则表达式的学习重点不是背完所有语法，而是建立一套拆解思路：

  • 字符：我要匹配哪些字符？用字面量、字符类还是预定义类？
  • 数量：重复几次？贪婪还是懒惰？
  • 位置：从哪开始、到哪结束？要不要用边界或断言？
  • 分组：哪些部分需要提取？是否需要命名和反向引用？

最后再强调一次：正则负责“看起来像”，标准库和解析器负责“确实是”。日期交给 datetime，IP 交给 ipaddress，HTML 交给解析器，正则只做它最擅长的那部分。这样写出来的代码，才既短又稳。
